# Project Architecture & Development Roadmap

## 1. Project Overview
**Lottery Lab** is a modern, high-performance web application for Thai Lottery statistical analysis. It provides real-time visualization of historical data, live streaming of lottery draws, and interactive features like lucky number generation and community chat.

## 2. Technical Architecture

### 2.1 Frontend Stack
- **Framework**: React 19 (Vite)
- **Language**: TypeScript
- **Styling**: Tailwind CSS 4 + shadcn/ui
- **Routing**: wouter (Lightweight client-side routing)
- **State Management**: React Context + Local State
- **Animations**: Framer Motion
- **Icons**: Lucide React

### 2.2 Folder Structure
```
client/
  src/
    components/           # Reusable UI components
      ui/                 # shadcn/ui base components
      CommentSection.tsx  # Live chat interface
      DanmakuOverlay.tsx  # Floating video comments
      LiveStream.tsx      # Video player wrapper
      TextToSpeech.tsx    # TTS utility
      StatsCharts.tsx     # Recharts visualizations
      ...
    contexts/             # Global state (Theme, etc.)
    lib/                  # Utilities (cn, formatters)
    pages/                # Page views (Home, NotFound)
    App.tsx               # Main application entry
    index.css             # Global styles & Tailwind config
```

### 2.3 Key Components
- **LiveStream**: Integrates YouTube Embed, Danmaku Overlay, and TTS.
- **DanmakuOverlay**: Renders floating comments with CSS animations.
- **TextToSpeech**: Manages browser `speechSynthesis` API for Thai voice reading.
- **StatsCharts**: Visualizes frequency data using Recharts.
- **LuckyNumberGenerator**: Algorithmic number generation based on stats.

## 3. Data Flow & State Management
- **Local State**: Used for UI interactions (e.g., chat input, toggle states).
- **Lifted State**: Chat messages are managed in `LiveStream` and passed down to `CommentSection` and `DanmakuOverlay` to ensure synchronization.
- **Mock Data**: Currently used for chat simulation and lottery stats.

## 4. Future Development Roadmap

- **Objective**: Replace mock data with live API sources.
- **Plan**:
  1.  **Lottery API**: Connect to a reliable Thai Lottery API (e.g., GLO Public API or reputable third-party) to fetch latest results and historical data.
  2.  **YouTube Data API**: Fetch the actual live stream ID dynamically instead of hardcoding.
  3.  **Backend Proxy**: Implement a lightweight Node.js proxy (if needed) to handle CORS and API rate limiting.

### Phase 2: User System & Community (Priority: Medium)
- **Objective**: Enable persistent user identities and social features.
- **Plan**:
  1.  **Authentication**: Implement login via Google/Facebook (using Firebase or Supabase).
  2.  **User Profiles**: Allow users to save favorite numbers and view personal stats.
  3.  **Real-time Chat**: Replace simulated chat with a real WebSocket-based chat server (Socket.io or Firebase Realtime Database).

### Phase 3: Advanced Analytics (Priority: Medium)
- **Objective**: Deepen the statistical insights.
- **Plan**:
  1.  **Machine Learning**: Train a simple model to predict "hot" numbers based on historical sequences.
  2.  **Personalized Dashboard**: Allow users to customize which charts they see on the homepage.
  3.  **Export Data**: Enable users to download statistical reports as PDF/CSV.

### Phase 4: Mobile App (Priority: Low)
- **Objective**: Expand reach to mobile app stores.
- **Plan**:
  1.  **PWA**: Optimize the current web app as a Progressive Web App (PWA) for installability.
  2.  **React Native**: Port the core logic to React Native for native iOS/Android performance.

## 5. Live Data Integration Strategy

To transition from mock data to real-world usage:

1.  **Lottery Results**:
    *   **Source**: `https://www.glo.or.th/api/` (Official) or scraped data from trusted news sites.
    *   **Implementation**: Create a `useLotteryData` hook that fetches on mount and caches results.

2.  **Live Stream**:
    *   **Source**: YouTube Data API v3 (`search` endpoint for channel ID `UC...`).
    *   **Implementation**: Query for "live" status of the official GLO channel every 5 minutes on draw days.

3.  **Chat System**:
    *   **Source**: Real user inputs via WebSocket.
    *   **Implementation**: Set up a `socket.io` server. When a user sends a message -> Broadcast to all clients -> Update `comments` state -> Trigger Danmaku & TTS.
